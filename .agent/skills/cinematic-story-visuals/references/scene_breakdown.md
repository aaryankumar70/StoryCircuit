## 1. Overview
Script -> **Understanding** (extract facts) -> **Bible** (lock the look) -> **Breakdown** (scenes with purpose) -> **Production instructions** (renderer-specific). Never skip a stage; never write production instructions before the bible exists.

## 2. Stage 1: Script understanding
Extract into a working table (not shipped):
| Item | Questions |
|---|---|
| Characters | Who? Named or unnamed? First-person narrator? Group? |
| Descriptions | What does the script actually say about appearance? (Everything else = ASSUMPTION) |
| Locations | Where? Indoor/outdoor? Era? Weather/time? |
| Time periods | Present, flashback, years later? |
| Timeline | Ordered events with narrated timestamps |
| Objects | Items that matter (document, scarf, door) |
| Events | What literally happens? (Never add events) |
| Emotional progression | Curve of feeling across the script |
| Suspense points | Questions the audience is holding open |
| Revelations | Which line reveals what? |
| Motifs | Recurring images the script implies |
| Transitions | Where time/place changes |

## 3. Stage 2: Visual bible
Create or load the bible (`../templates/visual_bible_template.md`, JSON per schema). For serialized work, load the existing bible and append; do not recreate it.

## 4. Stage 3: Scene breakdown
Each scene has: `scene_id`, narration/timestamps, `narrative_purpose`, `visual_description`, characters (id + state + presence), location + variant, `shot`, `camera_movement`, `lighting`, `palette`, `motion`, `transition_out`, `continuity_requirements`, optional `hidden_or_withheld` and `prompt`. See `../templates/scene_specification_template.json`.

## 5. Stage 4: Production instructions
Convert each scene to renderer language using the repository's real capabilities (see `transitions_and_motion.md` capability ladder). Output: `implementation_hints`, and where the pipeline wants, a renderer-specific adapter generated by the future agent. Never require an unavailable API.

## 6. Choosing scene boundaries
Start a new scene when any of these changes: **location, time/era, emotional beat, information revealed, point of view, or required camera idea**. Merge consecutive sentences that share all of them. Do **not** generate one scene per sentence.
- A short sentence can hold a long hold (stillness).
- A long sentence can span two scenes if the visual idea changes mid-sentence (split at a clause boundary).
- Keep one idea per scene.

## 7. Pacing targets for Shorts
| Total duration | Scenes | Average |
|---|---|---|
| 30 s | 5-8 | 4-6 s |
| 45 s | 7-10 | 4-6.5 s |
| 60 s | 9-13 | 4.5-6.5 s |
Minimum scene length 2.0 s (except a deliberate 1 s cut at a climax); maximum 9 s unless it is a single held shot with changing light. Hook scene (first 1-3 s) must show a concrete, intriguing image, not a title card.

## 8. Worked mini-example
Narration: "I went back to the one person I knew had heard it. He never mentioned that bus. Not once."
- Understanding: Character = friend (existing), location = friend's kitchen (existing), emotion = tension, withheld = the story.
- Breakdown: s01 (road, resolve, 0-3 s) -> s02 (kitchen wide, friend under lamp, 3-8 s). Two scenes, not three, because "He never mentioned..." continues the same idea.

## 9. Common mistakes
1. One image per sentence (choppy, expensive).
2. Showing the story instead of its effect.
3. Changing lighting direction between consecutive shots of the same room.
4. Defining characters after scenes are written (inconsistency).
5. Forgetting `hidden_or_withheld` on reveal scenes.
