CurioLoop Privacy Policy

Effective Date: November 10, 2026 • Application Type: Local-First Desktop Production & Publishing Workflow

1. Overview and Scope

CurioLoop is a local-first short-form educational video production and YouTube publishing application operated on the creator's own Windows workstation. CurioLoop does not operate a remote SaaS backend, shared cloud user database, third-party analytics tracker, or advertising network.

This static informational website (the homepage and this Privacy Policy) does not set tracking cookies, collect form submissions, or run client-side behavioral scripts.

2. Google OAuth Authentication & Scopes Requested

To upload and schedule videos on a creator's YouTube channel, CurioLoop uses Google OAuth 2.0 via the Installed Desktop Application flow with offline access (access_type=offline). Depending on how the operator authorizes the client, CurioLoop requests only YouTube-related scopes:

OAuth Scope Information Accessed Purpose in CurioLoop
https://www.googleapis.com/auth/youtube.upload Write access to upload MP4 videos and initial video metadata/status Direct resumable MP4 upload of Shorts, titles, descriptions, tags, categories, private staging, and initial status.publishAt scheduling on insert.
https://www.googleapis.com/auth/youtube.readonly Channel uploads playlist ID, recent uploaded video titles/IDs, upload/privacy/rejection status, and scheduled publishAt timestamps Confirm YouTube scheduled publication times via API readback, verify upload health, and prevent duplicate video uploads.
https://www.googleapis.com/auth/youtube.force-ssl (optional, when authorized) Video status update capability on videos owned by the authorized channel Cancel or update an existing video's scheduled status.publishAt setting while keeping the video private.

During authorization and health checks, CurioLoop contacts Google's official OAuth endpoints (https://oauth2.googleapis.com/token to exchange or refresh short-lived access tokens and https://oauth2.googleapis.com/tokeninfo to verify which scopes were granted). CurioLoop does not request access to Gmail, Google Drive, Google Contacts, Calendar, or unrelated Google account data.

3. Video Uploading, Scheduling & Channel Data Usage

When live YouTube publishing is enabled, CurioLoop transmits rendered MP4 files and user/generated video metadata directly from the operator's local PC to YouTube Data API v3 endpoints (videos.insert, channels.list, playlistItems.list, videos.list, and when updating or cancelling schedules, videos.update).

  • Duplicate Prevention: Recent items in the channel's uploads playlist are inspected by video title and matched against local database records before initiating an upload so network retries do not create duplicate uploads.
  • API Confirmation: CurioLoop queries videos.list to confirm YouTube actually recorded the expected privacyStatus, uploadStatus, and publishAt timestamp before marking a slot scheduled.
  • Strict Privacy Default: Configuration defaults to private status and scheduled videos remain private until their confirmed publication time on YouTube.

4. Local Credential & Application Data Storage

CurioLoop stores credentials and operational records strictly locally on the operator's Windows machine—not on external CurioLoop servers:

  • OAuth Credentials (.env): The Desktop OAuth Client ID, Client Secret, and Refresh Token are saved locally in an untracked .env file protected by operating system file permissions and excluded from Git via .gitignore.
  • Token Health State (data/token_state.json): Records non-secret health status, check timestamps, granted scope URIs, and reauthorization warning messages.
  • Production & Schedule Records (data/*.json, data/scheduler.log): Stores topic titles, scripts, verified research source URLs, rendered file paths, YouTube video IDs, QC metrics, and scheduler state on disk.
  • Local Dashboard Isolation: The optional management dashboard binds exclusively to 127.0.0.1 (localhost), enforces a locally generated X-Studio-Auth secret on mutating routes, and redacts API keys, access tokens, refresh tokens, and client secrets from HTTP status payloads.

Transparency Note: Local .env and JSON state files are stored as plain local files under the operator's Windows user directory rather than inside a hardware-backed OS credential vault; file confidentiality relies on workstation access controls and any host disk encryption enabled by the operator.

5. Optional Third-Party Integrations & External Transmissions

CurioLoop performs speech synthesis (Kokoro ONNX), word alignment (Whisper), frame rendering (local headless browser + FFmpeg), and quality checks locally without sending video files to external SaaS services. In addition to Google OAuth and YouTube Data API v3, the application contains two optional integrations:

  • Google Gemini API (Optional): Only active if the operator supplies a GEMINI_API_KEY. When configured, CurioLoop sends text prompts (topic discovery, educational script generation, and description drafting) to https://generativelanguage.googleapis.com. YouTube OAuth tokens and channel credentials are never included in Gemini prompts. When unconfigured, CurioLoop falls back to a local curated catalog with zero Gemini requests.
  • Meta Instagram Graph API (Disabled by Default): CurioLoop includes optional Instagram Reels support that defaults strictly to INSTAGRAM_PUBLISHING_MODE=disabled, making zero network requests. If explicitly configured and enabled by the operator, credentials and video upload calls are sent to https://graph.instagram.com.

CurioLoop does not sell personal information, does not use Google user data for advertising or marketing, and does not share Google OAuth tokens or YouTube channel data with data brokers or third-party platforms.

6. Google API Services User Data Policy & Limited Use

CurioLoop's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. Access is restricted solely to user-facing video upload, scheduling, and verification features authorized by the account owner.

7. Data Retention & Deletion

OAuth credentials, generated scripts, rendered MP4 videos, and scheduling logs remain on the operator's local workstation until deleted or replaced by the operator. Because CurioLoop maintains no remote server database, deleting the local .env, data/, and output/ files permanently deletes all locally retained application data and credentials. Videos already uploaded to YouTube remain subject to YouTube's Terms of Service and can be deleted or changed to private at any time in YouTube Studio.

8. Revoking Google Account Access

You can revoke CurioLoop's access to your Google/YouTube account at any time:

  • Visit https://myaccount.google.com/permissions while signed into your Google account.
  • Locate CurioLoop under Third-party apps & services and click Remove access.
  • On the local machine, remove or clear YOUTUBE_REFRESH_TOKEN in .env (and optionally delete data/token_state.json). Once revoked, Google rejects token refreshes (invalid_grant) and CurioLoop automatically halts live uploads.
